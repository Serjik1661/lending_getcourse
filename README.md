# Прополис · Здоровье

Статический лендинг для проекта `propolis-doctor.ru`.
Сайт опубликован как GitHub Pages project site: `https://serjik1661.github.io/lending_getcourse/`.

## Что это за проект

- Главная страница с героем, видео, блоками преимуществ, программой, автором, отзывами, CTA, FAQ и футером.
- Дополнительные страницы: контакты, политика конфиденциальности, условия, дисклеймер, оферта, возврат, техническая страница.
- Форм и оплаты на сайте нет. Основной CTA должен вести на GetCourse после получения рабочей ссылки от заказчика.

## Ключевые файлы

- `index.html` - главная страница.
- `contacts.html` - контакты, реквизиты и карта.
- `privacy.html` - политика конфиденциальности.
- `terms.html` - пользовательское соглашение.
- `medical-disclaimer.html` - медицинский дисклеймер.
- `offer.html` - черновик оферты.
- `refund.html` - черновик возврата.
- `thank-you.html` - техническая страница, в публичном сценарии не используется.
- `404.html` - страница ошибки.
- `offline.html` - офлайн-страница.
- `sw.js` - service worker и кэширование статических файлов.
- `robots.txt` и `sitemap.xml` - SEO и индексация.
- `serve_local.py` - локальный статический сервер с clean URL маршрутизацией.
- `start_site.bat` - запуск локального сервера в Windows.

## Структура папок

- `assets/css/` - стили.
- `assets/js/` - меню, cookie banner, карта, базовая логика, регистрация service worker.
- `assets/icons/` - иконки, логотипы, UI-элементы.
- `assets/images/` - все изображения сайта.
- `assets/videos/` - видеофайлы.
- `docs/archive/` - архивные снимки прошлых версий страницы.
- `scripts/` - служебные проверки и утилиты.

## Как устроены изображения

Нынешняя схема именования:

- `assets/images/hero/` - hero-изображения.
- `assets/images/course/` - обложки, иллюстрации уроков и постер видео.
- `assets/images/doctor/` - фото автора и связанные кадры.
- `assets/images/reviews/` - фотографии для отзывов.
- `assets/images/cta/` - изображения для CTA-блоков.
- `assets/images/og/` - изображение для предпросмотра в соцсетях.

Правило именования:

- `section-purpose-variant.ext` для публичных ассетов.
- `*-photo.*` для фотографий людей.
- `*-share.*` для социальных превью.
- `*-source.*` для исходников/сырья, если файл нужен как рабочая версия, но не является финальным публичным ассетом.

В `assets/images/` также могут лежать вспомогательные или legacy-файлы, которые не подключены к публичным страницам. Перед удалением или переименованием любого изображения всегда проверяй ссылки по репозиторию.

Примеры актуальных файлов:

- `assets/images/og/og-propolis-share.png`
- `assets/images/doctor/doctor-office-portrait.webp`
- `assets/images/reviews/review-maria-photo.jpg`
- `assets/images/reviews/review-olga-photo.jpg`
- `assets/images/reviews/review-anna-photo.jpg`

## Что важно не сломать

- Все внутренние ссылки должны быть относительными, чтобы сайт работал на GitHub Pages.
- После добавления или удаления публичного изображения нужно проверить HTML-ссылки и, если файл попадает в публичный сценарий, список в `sw.js`.
- Если меняется service worker или его список ассетов, нужно обновить версию кэша и registration URL, чтобы не оставался старый кэш в браузерах.
- Кнопки GetCourse и ссылки на маркетплейсы должны вести на реальные URL только после подтверждения заказчиком.
- Внешние сервисы, включая карту, должны грузиться только после согласия пользователя.

## Локальный запуск

### Вариант 1

Запусти `start_site.bat`.

### Вариант 2

```powershell
python serve_local.py
```

После запуска открой:

```text
http://127.0.0.1:8787/
```

Локальный сервер нужен, чтобы clean URLs вроде `/contacts` открывались как соответствующие `.html`-страницы.

## Перед публикацией

- Проверить, что `index.html` и служебные страницы открываются без 404.
- Проверить, что кнопки и якоря ведут на правильные разделы.
- Проверить мобильную версию после любых изменений в hero, видео и CTA.
- Проверить, что service worker не держит старую версию после обновлений.
- Проверить, что в текстах нет незапланированных медицинских обещаний.
- Убедиться, что в репозиторий не попали черновики, мусорные медиа и временные файлы.
